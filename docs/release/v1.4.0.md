## Data Safety

- Strategy persistence is database-backed.
- Tests use isolated temporary databases.
- Destructive clear operations are guarded.
- Schema migrations are additive and backed up.
- User-deleted data uses lifecycle controls.

## Important Semantics

`HOLD_PREVIOUS_ALLOCATION` uses Starting Allocation until the first resolved
target exists. On later no-match dates it keeps the previous resolved target.
Fallback is active only when `USE_FALLBACK` is selected.

Requested calendar dates and effective trading dates may differ. The effective
range remains inside the requested range and is non-empty when execution is
available:

```text
effective_start >= requested_start
effective_end <= requested_end
effective_start <= effective_end
```

## Upgrade Notes

The V1.4 migration preserves Strategy, Draft, and StrategyVersion identity.
Keep a database backup before upgrading. V1.4 does not reconstruct historical
StrategyVersions that were physically missing before durability hardening.

## Known Limitations / Deferred

- Walk-forward optimization.
- Monte Carlo analysis.
- Automatic strategy selection.
- More advanced portfolio optimization.
- Historical StrategyVersions that were already physically missing before
  durability hardening are not reconstructed.
