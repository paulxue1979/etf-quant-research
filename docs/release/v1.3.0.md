# ETF Quant Research System V1.3

## Release Status

V1.3 is ready for an annotated `v1.3.0` tag after explicit release approval. This
document prepares the release but does not create a tag, push a branch, or create
a GitHub release.

## Highlights

V1.3 extends the existing deterministic research pipeline without adding live
trading or automatic strategy selection:

- generic signal-source and execution-asset roles;
- daily and completed-week timeframes with no-lookahead as-of semantics;
- explicit Regime State Machine with deterministic arbitration;
- parameterized weekly Value Zones, hysteresis, and Recovery Hold;
- multi-asset regime allocations with Cash distinct from assets such as SGOV;
- versioned position and rebalance policies;
- controlled deterministic Grid Search with structured constraints;
- IS-only Heatmap, Pareto, Stability, and Sensitivity analysis;
- Portfolio Value, Capital Invested, and Investment Profit comparison;
- Signal, Execution, Rebalance, Contribution, Allocation, and Regime markers;
- bounded metadata-based history pagination and optimization projections.

## Strategy Modeling And Multi-Timeframe Data

Strategy schema 2.0 adds explicit asset roles, operand timeframes, regimes,
transitions, value zones, and regime allocations. Schema 1.0 remains readable
and preserves its original wire shape and content identity. Assets without roles
retain the legacy `BOTH` capability, and operands without timeframes retain
`DAILY` semantics.

Weekly data is deterministically derived from validated daily data. Only a
completed exchange-calendar trading week is visible. A holiday-shortened final
session completes that week; an incomplete current week remains invisible.
Daily evaluation uses the latest completed weekly value available as of that
date. V1.3 does not infer or predict an unfinished weekly bar.

## Regime And Position Management

The state machine produces one active regime and one canonical target per
evaluation date. Transition arbitration is deterministic, same-day cascades are
prohibited, and a no-transition date preserves state. Value Zone priority ties
are rejected rather than silently resolved.

The position policy can independently enforce minimum target change, actual-to-
target drift, maximum one-way trade budget, minimum ledger Cash reserve, and
per-asset allocation constraints. A turnover breach uses hard suppression and
does not rewrite the strategy target. Regime change, contribution, drift, and
schedule triggers are aggregated into one RebalanceDecision and one order plan.
Contributions enter Cash first and never create a synthetic strategy signal.

## Parameter Research And Robustness Analysis

Grid Search uses a frozen parameter space, deterministic Cartesian ordering,
typed parameter bindings, structured Sum/Ordering/Budget constraints, semantic
deduplication, and explicit preflight counts. The default executable limit is
100 candidates, the hard limit is 1,000, and the theoretical-space guard is
1,000,000. Exceeding a limit fails explicitly; candidates are never silently
truncated.

Execution is sequential and preserves completed results across individual
candidate failures or cancellation. Optimization projections read lightweight
IS result summaries and are capped at 1,000 candidates. Heatmap performs no
interpolation or silent aggregation. Pareto honors each metric's direction,
including canonical negative Max Drawdown. Stability uses direct neighbors;
Sensitivity preserves parameter gaps. Filtering does not rewrite topology.

Candidate selection remains an explicit researcher decision. V1.3 does not
automatically choose a best strategy.

## Research Integrity And Official OOS

The controlled workflow is:

```text
Frozen Protocol -> Deterministic Grid/IS -> Researcher Selection
-> Strategy Freeze -> Controlled OOS -> Immutable Official OOS Result
```

Grid generation, preflight, filtering, Heatmap, Pareto, Stability, Sensitivity,
and selection inputs are IS-only. The selected StrategyVersion content hash,
BacktestConfig, asset roles, timeframes, value zones, allocation, and rebalance
policy are frozen before OOS. Official OOS cannot re-optimize or mutate them.

An OOS execution window currently starts independently from the frozen
strategy's `initial_regime`. Pre-OOS state warmup is not part of V1.3.

## Wealth Accumulation And Explainability

Comparison schema 2.1 can opt into Portfolio Value, Capital Invested, and
Investment Profit alongside canonical base-100 TWR and drawdown. Contributions
step invested capital on their effective trading date and do not create profit.
Equal final capital with different contribution timing is explicitly identified
as `TOTAL_CAPITAL_EQUAL_BUT_TIMING_DIFFERS`.

The independent marker endpoint projects immutable BacktestRun evidence into
Signal, Execution, RebalanceDecision, Contribution, Target Allocation, Actual
Allocation, and Regime markers. Signal and execution dates remain separate;
suppressed rebalances do not create execution markers.

## API Additions

V1.3 adds the following additive surfaces while retaining V1.2 requests:

- `/research/experiments/{experiment_id}/grid/*` for preflight, prepare,
  execute, cancel, progress, and templates;
- `/research/protocols/{protocol_id}/experiments/{experiment_id}/optimization/*`
  for results, Heatmap, Pareto, Stability, and Sensitivity;
- `/research/backtests/{backtest_run_id}/report/markers` as an independent,
  opt-in marker projection;
- lightweight experiment result summaries and paged metadata history;
- optional wealth fields in comparison schema 2.1.

Existing report schema 1.0 remains valid. Marker data is not injected into old
report payloads, and clients that do not request comparison wealth continue to
receive the established comparison behavior.

## Database Upgrade Notes

The V1.2 SQLite database upgrades in place. **DO NOT delete the existing
database or historical BacktestRuns.**

V1.3 adds:

- `backtest_run_metadata`, a derived read model keyed by `backtest_run_id`;
- metadata indexes for strategy, version, experiment, and candidate history;
- deterministic ordering indexes on `backtest_runs`;
- `grid_search_definitions` and `grid_search_candidate_plans`, created when the
  Grid Search repository is first used;
- no destructive change to canonical `backtest_runs.run_json`.

Repository initialization runs idempotent `CREATE TABLE/INDEX IF NOT EXISTS`
schema checks. New BacktestRuns write canonical `run_json` and metadata in one
transaction. Legacy runs remain readable before backfill, although lightweight
history reports metadata as unavailable for a missing projection.

Legacy metadata backfill is explicit and bounded through
`BacktestRepository.backfill_metadata(limit=...)`; there is no separate release
CLI. Operators may invoke the existing repository method in batches of at most
1,000 rows and repeat until `inserted == 0`. It uses `INSERT OR IGNORE`, is
idempotent and retry-safe, does not update `run_json`, and rolls back the batch
with a controlled error if a canonical record is corrupt.

The validated local database has 164 canonical runs and 164 metadata rows,
zero missing or orphan projections, projection version `phase-11g.1`, and a
successful SQLite integrity check.

## Upgrade Procedure

1. Back up the existing SQLite file using the project's normal local backup
   procedure.
2. Update the checkout to the approved `v1.3.0` release after the tag exists.
3. Refresh Python dependencies with `.venv/bin/python -m pip install -e ".[dev]"`.
   This installs the new `exchange-calendars>=4.13.2,<4.14` dependency.
4. Run `pnpm install` in `frontend/` using the declared pnpm 11 toolchain.
5. Start the application normally. Additive schema initialization occurs when
   the repositories are constructed.
6. Run the explicit bounded metadata backfill only when legacy history rows lack
   projections. No database deletion or canonical artifact rewrite is required.

## Financial And Accounting Compatibility

Canonical analytics implementations for TWR, XIRR, CAGR, drawdown, Sharpe,
Sortino, Calmar, turnover, exposure, and benchmark were not changed between
`v1.2.0` and V1.3. Backtest execution retains `Signal(T) -> next trading session

execution constraint and never changes canonical TargetAllocation.

## Known Limitations

### Design Limitations

- Grid execution is sequential. The default limit is 100 candidates and the
  hard limit is 1,000.
- An OOS window resets to the frozen strategy's initial regime; pre-OOS state
  warmup is deferred.
- Marker projection is opt-in and is not included in comparison responses by
  default.
- Dataset references are immutable provenance references but do not yet provide
  a complete independently versioned artifact store.

### Deferred Capabilities

- Walk-forward analysis, Monte Carlo, AI optimization, random/Bayesian/genetic
  search, live trading, and broker execution are not implemented.
- Distributed Grid Search is not implemented.

### Environment Limitations

- Fresh Tiingo access depends on the user's DNS, HTTPS connectivity, and local
  API-key configuration. Local cache acceptance is available offline.

### Known Non-Blocking Issues

- Canonical `run_json` storage grows with long histories; metadata avoids using
  those payloads for list and optimization reads but does not compact artifacts.
- The Vite build retains a JavaScript chunk warning above 500 KiB.
- Repository-wide Ruff format has 37 pre-existing files outside the release
  change set; Ruff lint and all V1.3 modified Python files pass.
- Narrow charts can render tight end labels without causing page overflow or
  blocking controls.

## Release Decision
