# ETF Quant Research System v1.4.6

## Controlled StrategyVersion Creation

Codex MCP can prepare and read a durable StrategyVersion creation request for
an exact Strategy ID. The request binds the saved Draft revision and hash, the
latest immutable Version ID and hash, and a canonical Draft snapshot. Explicit
`client_request_key` values make retries idempotent while preserving rejected
requests and allowing a separately authorized new intent.

Only a user action in the local Strategy Lab can approve or reject a request.
Approval revalidates the Draft and Version baseline, then creates the canonical
immutable StrategyVersion and records the request transition in one transaction.
STALE protection, concurrent approval serialization, duplicate-approval
idempotency, Version History integration, and cold-restart read-back are covered.
The MCP surface has prepare/read tools but no approve or direct-create tool.
Preparing a request never runs a Backtest.

The Python package, frontend package, FastAPI application, and Operator
`backend_version` are aligned at 1.4.6. The independent bridge version remains
0.2.0. The release gate tests both consistency and the explicit target version.

This is a controlled local Operator feature, not automated trading, autonomous
strategy optimization, or a Grid Research loop. It does not change Strategy
evaluation, rebalance, Backtest, monthly DCA, TWR/XIRR, Peak Drawdown,
HOLD_PREVIOUS_ALLOCATION, Experiment/Grid, Selection, Freeze, or OOS semantics.
No database migration is required.

## Known limitations

- The local Origin approval gate assumes a trusted local environment; it is not
  public-network user authentication.
- Exact Strategy IDs are required because strategy names need not be unique.
- Retry the same intent with the same `client_request_key`; a new intent after
  rejection requires a new key.
- MCP cannot create an immutable StrategyVersion without browser approval.
