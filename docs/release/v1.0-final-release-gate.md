# ETF Quant Research System V1.0 Final Release Gate

## Release Scope

V1.0 covers bounded historical ETF data access, indicator calculation, declarative strategy evaluation, deterministic backtesting, performance analytics, Strategy Lab, Backtest Lab, experiment research, Research Protocol freeze/selection, and the official read-only OOS Research View.

The release does not include live trading, broker execution, walk-forward, Monte Carlo, benchmark, tax, intraday, or automated strategy selection.

## Architecture

The runtime boundaries are `data`, `indicators`, `strategies`, `backtest`, `analytics`, `research`, `backend`, and `frontend`. Strategy evaluation owns signals and allocations; the Backtest Engine owns orders, fills, positions, cash, and accounting; Analytics consumes persisted backtest results; the frontend renders backend responses.

The OOS chain is frozen protocol and strategy identity, claimed execution, bounded data and warmup, strategy evaluation, `Signal(T) -> T+1 open` backtest execution, analytics, atomic official finalization, and a read-only official view sourced from the persisted BacktestRun.

## Capability Matrix

Implemented and covered by unit, integration, or audit tests:

- Data: Tiingo client, disk cache, normalization, OHLCV validation, raw/adjusted price fields, retry/error mapping, and common-date alignment.

- Research: immutable strategy versions, deterministic experiments, researcher-owned selection, protocol freeze and handoff, IS-only execution, OOS one-shot claims, leases, stale-worker protection, atomic finalization, and immutable provenance.
- UI/API: Strategy Lab, Backtest Lab, comparison diagnostics, experiment research, protocol workflow, and official OOS Research View.

## Five-ETF Acceptance

The generic multi-asset path supports `QQQ`, `TQQQ`, `SPY`, `IWM`, and `SGOV`, with strict common-date intersection and no forward/backward fill. A live five-ETF acceptance run was not produced in this environment because Tiingo DNS resolution was unavailable. No IDs or real-data results are fabricated.

## Research Integrity

Research records are immutable by identity. IS candidate execution cannot consume OOS performance, selection is explicit and researcher-owned, and OOS data is firewalled to the frozen OOS range plus indicator-only warmup. Official OOS finalization creates one source-of-truth BacktestRun and a read-only view; it does not recompute or mutate results on read.

## Installation and Operation

Prerequisites are Python 3.12+, Node.js 20+, and pnpm 10+. Configure `TIINGO_API_KEY` in a local `.env`; never commit it. Install backend dependencies with `python3.12 -m venv .venv` followed by `.venv/bin/python -m pip install -e ".[dev]"`. Start FastAPI with `.venv/bin/uvicorn backend.app.main:app --reload` and the frontend with `pnpm install` then `pnpm dev` under `frontend/`.

## Known Limitations

- Tiingo availability depends on external network/DNS and credentials: external integration was blocked during this audit.
- The V1.0 data provenance records request/source metadata but does not provide an immutable dataset snapshot store.
- SQLite is appropriate for single-machine research, not high-concurrency production serving; formal schema migrations are not included.
- No walk-forward, Monte Carlo, benchmark, live trading, broker integration, tax model, intraday engine, or corporate-action-independent archive.
